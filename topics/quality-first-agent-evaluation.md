# Agent 优化：先过质量门，再比较成本

整理于 2026-09-19。来源：PAW 学习仓库第 42 课。原课解释历史 `evaluate_path_search` 选择器；这里总结实验方法，不复用私人实验数字。[来源说明](../sources/local-learning-site.md)。

## 便宜为什么不一定值得保留

用户需要的是完成任务。在必要业务条件失败时，低价不能抵消失败。评测要先冻结任务、数据、模型配置、工具条件、重试规则和 verifier，再比较候选。

一个合成例子：基线通过全部 10 条规则；候选 A 更便宜却只过 9 条；候选 B 通过全部规则且较便宜；候选 C 缺少质量结果。A 应拒绝，C 保持未知，B 才有资格进入成本比较。这里没有真实费用或产品收益声明。

## 选择流程

```text
核对实验身份和控制条件
  → 检查质量与可靠性硬门
  → fail：拒绝；缺证据：未知
  → 合格候选才比较软目标
  → 输出选择、证据和适用范围
```

原课的选择器消费已有结果，不生成候选、不执行 Agent，也不自动安装 Keep 的配置。评分 owner 判断业务是否通过，选择 owner 比较已声明目标，交付 owner 决定版本应用。引用非空也不证明引用内容真实，测量证据仍需可信来源。

## 四个容易混淆的结论

- 工具返回成功，不等于业务验收通过。
- 检索指标改善，不等于答案与引用通过。
- 在 Validation 中选出的最好候选，只是该搜索范围内的 best known，不是全局最优。
- 用过的保留集不能继续当未触碰测试集；候选选择与泛化评价要分开。

一次只改一个因素更便于归因；必须同时改变多个因素时，应明确结论只覆盖组合。不同实验的成本收益不能随意相乘。失败样本也必须进入合同规定的成本与成功率分母。

## 和最近学习的关系

Code Mode、Schema 披露、Jev 决策与 GIS 数据放置都可能降低成本，但要先证明任务结果仍满足要求。延迟可以记录为诊断指标，是否作为硬门或排序目标要由事先约定的实验合同决定。

费曼问题：没有候选过门，保留基线是否就证明基线已满足全部新要求？

不证明。它可能只是缺少足够证据替换当前方案。应保留不足证据的结论，明确未满足或未测得的条件，而不是把“没有更好候选”改写为成功。
